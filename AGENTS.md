# Perch: guide for people and agents picking this up

Perch is a macOS notch app. When a developer comes back to their Mac, it tells them where they left off across their coding agents (Claude Code, Codex, OpenCode, pi) and lets them jump back in, reply, snooze, or change settings, all from the notch. It is a portfolio-quality project: the bar is delight, polish and restraint, not feature count. Four jobs, in order: where was I, jump back in, what needs me, answer from the notch. Sessions from the Claude app (Code), the Codex app, and Claude Code, Codex, OpenCode or pi in any terminal, including inside the herdr and cmux multiplexers.

Read this file first. `README.md` has install and usage.

## How the work is done here

1. **Show it in the design page first.** New UI or a visible change goes into `ui/design.html` (the real UI with sample data) and gets looked at before it is built into the app. Whenever you build or change a design there, open the design page for the owner yourself (the browser pane, on the scenario that shows it) and say where to find it; do not only describe it or draw a mock-up in chat. Serve it from this checkout's own `ui/` on a free port (`lsof -iTCP:8765` first: another worktree may already hold it and would show its old files). The owner will say "build it" when approved. Small fixes and bugs can go straight in.
2. **Look at it before you say it is done.** Render the design page in a browser (`cd ui && python3 -m http.server 8765`, open `/design.html`) and check each state. Say plainly what you checked and what you did not. Mock-ups sit on Raycast wallpapers (`ui/wallpapers/`, from raycast.com/wallpapers). The README's GIF is filmed from the design page (`design.html?record` plays a set flow): `./scripts/record.sh` (needs ffmpeg; headless, about 22 s, nothing shows on screen).
3. **Commits:** one-line messages, no mention of AI or co-authors. Commit after every working step.
4. **Tests must stay green:** `swift test`.
5. **Opening a PR:** the body follows `.github/pull_request_template.md` and carries a demo filmed from the design page. Agents use the `open-pr` skill (`.claude/skills/open-pr`): fill every section from the diff, `gh pr create --body-file`, then `./scripts/pr-demo.sh --publish`, which films the scenarios the branch added or changed in `ui/design.html` (or the ones named), one after another with a caption, and writes a GIF, an MP4 and a still of each into the PR's Demo section. The media lives on the `pr-media` branch, never main. A hook (`.claude/hooks/pr-body-check.py`) refuses `gh pr create` without the template. No visible change: Demo says so.

## Architecture

```
Sources/PerchCore   Pure logic, no UI, fully tested.
  NotchMachine        State machine: idle, open, switcher, restoring, onboarding, settings.
  NotchGeometry       Panel and tab sizes, hover rects. Takes ScreenInfo so it is testable. ScreenPicker: which display the cursor is on, the top edge counted (a cursor aimed at a notch rests at y == maxY, which CGRect.contains leaves out).
  Agent               Each agent's names, resume command, whether Perch answers it from the notch, how to spot its process.
  Project, Transcript Session model, JSONL parsing (Claude Code and Codex), recap text, git parsing.
  OpenCode, Pi        OpenCode's SQLite database (read-only) and pi's session files, into the same SessionDigest.
  Conductor           ConductorSessions: Conductor's SQLite database (read-only) maps a Claude Code session id or Codex thread id to its workspace.
  LiveStatus          Hook events (HookEvent), what an agent asks (Ask: words for the card, the reply JSON), live status per session.
  SessionScan         SessionScanner: which sessions get a row (Claude app list, Codex threads, OpenCode, pi), tail reading, caches.
  Focus               Which running session you are in: a Spot (cmux surface, herdr pane, tty) compared with what is in front (Looking); unsure means every live session in that app is a maybe.
  Shortcut            The shortcut that opens Perch: a tap of two or more modifiers (default Command+Option) or a key combo; the rules (what is refused and why), ModifierTap (a tap counts only when pressed from nothing with no other modifier or key, keys other apps' hotkeys take counted by the system's key-down counter, so another app's Command+Option+Shift+L never opens Perch) and ShortcutRecorder, which turns key events into a recording. Recorded from Settings (Change opens a full-card page, `onbOpen` step 3 only) or onboarding step 3; HotkeyService applies it and pauses every Perch hotkey while recording.
  ScreenTarget        Which screen Perch opens on (ShowOn: the mouse's, the active window's, or a display by its UUID), with fallbacks to the mouse; window-list rects to Cocoa's.
  Place               Where a running agent lives (herdr pane, cmux surface, tab) from its environment; which process is which session (Running); herdr's status (HerdrStatus).
Sources/Perch       The AppKit shell.
  main.swift          Launch flags, hotkeys, status item menu, first-run onboarding.
  NotchController     Owns the machine, the panel, the WKWebView, timers, hover, keys, refresh.
  RealSessionProvider Runs the SessionScanner, keeps per-app counts and what each card was built from.
  HookServer          Unix socket (~/.config/perch/perch.sock) the hooks post to; holds a request open until you answer. HookInstaller writes the hook entries,
                      and for OpenCode and pi Perch's own plugin file (PerchPlugins).
  FocusProbe          Reads what is in front, a second apart off the main thread: focused cmux surface, Terminal/iTerm2 tab tty, Ghostty folder, herdr's focused pane, the Claude window's session (Accessibility). A reading older than 3 s is not trusted.
  Terminals           Running agents from the process table (LiveSessions), going back to them (tab, herdr pane, cmux surface), typing into them.
  ClaudeComposer      A reply into a Claude app session through Accessibility, Claude's window left behind.
  Snapshot            The JSON Swift sends to the page. The page never decides anything.
  Preferences         UserDefaults: onboarded, character, enabled apps, idle minutes.
  HotkeyService       Carbon hotkeys and the Command+Option tap (needs Accessibility).
ui/                 The interface, plain JS and Tailwind v3 (shadcn-style classes), Inter bundled.
  app.js              All rendering. window.perch.apply(snapshot) draws; messages go back through
                      webkit.messageHandlers.perch. A browser-only dev harness (window.perchDev) runs it with sample data.
  input.css           Tailwind plus the notch, glow and character styles.
  orbs.js             Thinking Orbs (thinkingorbs.com, MIT), vendored as a plain script: the orb beside a working step.
  design.html         The design page. Scenarios for every state.
```

Data flow: Swift decides state (`NotchMachine`), builds a `UISnapshot`, calls `window.perch.apply(json)`. The page draws and posts events (`confirm`, `snooze`, `reply`, `settings`, `onb`, `character`, `source`, `setting`, ...). Handle new events in `NotchController.userContentController`.

Sessions: one row per session, up to 15. The list goes by section, what needs you, today, earlier, newest first in each (`ListFilter.ordered`); a row leads with the session's title and how long ago; at the right, a ring for its status (`rowMark`: the spinner while it works, a check when it finished and you have not seen it, ? for a question, the prompt for a command waiting for your OK, ! for anything else waiting) and its project in grey. About five show at a time. Claude: the Claude app's own list (`~/Library/Application Support/Claude/claude-code-sessions`) decides, archived ones skipped; transcripts are `~/.claude/projects/*/<id>.jsonl`. Codex writes `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`; `codex exec` runs and subagent threads are skipped (`SessionDigest.headless`), thread names come from `~/.codex/session_index.jsonl`. A chat started without a project (Claude scratch workspace, Codex dated folder) is named by its title (`Recap.isFolderless`). While a session works, the card says what it last said it is doing and a Now row shows the step (`Activity.step`), with a Thinking Orb beside it in the character's colour whose state follows the step (`orbFor`; `ui/orbs.js` is the MIT plain JS build of thinkingorbs.com, vendored). Typing in the list narrows it (`ListFilter`). Reply shows the agent's own last message as written (`Project.said`, line breaks kept), with your own last message above it as a bubble, a scroll up (`Project.asked`; a markdown table scrolls in its own window both ways, header kept, `mdTable`; bullet (`-`, `*`, `•`) and numbered lists draw with grey markers, code takes the character's colour (`.md-code`, `--cr`), deeper indents nest, an indented line carries on its item, a list may follow a bold line with no blank line, a `#` heading is a bold line, `mdLines`); a reply to a terminal clears the card and the notch gulps the words. What you type in a reply is that session's draft until sent (`drafts`, in memory): closing the card keeps it, Esc and R bring it back, and a file pasted from Finder or dropped on the card goes in as its path (`CardWebView`). A press outside the card closes it on release, so a file dragged from Finder can still land on it, and files dragged to the notch open the card like a hover. Files over the card open its reply and light the field, more so right on it, while the character watches them (app.js `dragOver`; the design page plays a pretend drag). Command+Option within five minutes of putting the card or list away brings it back as it was, the same session's card or the list with its filter and row, a reply open with its words (`PutAway`); resting on the notch brings back a reply you were writing. Pick up, a reply sent, an answer or Not now forget it. A reply to a Claude app session goes in with Claude's window behind (`ClaudeComposer`: it presses the session's sidebar row, fills the ProseMirror field (a draft already there is set aside and put back after Send), presses Send, then goes back; the page's address must end in `local_<id>` before it writes and before Send, otherwise it falls back to pasting). It leans on Claude's page internals, so a Claude update can send it to the fallback. Whenever Perch has to bring an app forward to reply (the paste fallback, a session resumed in a new terminal tab), it puts you back in the app, window and Claude session you were in (`WhereYouWere`); a fallback never presses Return over a draft. Without Accessibility, Send reads Allow and send and holds the reply until access is on. Tests in `SessionScanTests` build a fake home folder: add one there for any new way a session can go missing. Small talk with no tool use is skipped (`Recap.isTrivial`). App icons and Codex itself are found by bundle id: Codex can be installed as `Codex.app` or `ChatGPT.app`. Pick up opens `claude://code/continue?session=local_<id>` or `codex://threads/<id>`. A terminal session (`Project.terminal`) goes back to where it runs while it runs (a herdr pane or cmux surface exactly, Terminal and iTerm2 by tty, Ghostty by folder, Warp by switching tabs with Command+1 to 9 and reading each one's title and text through Accessibility (`WarpTabs`: Warp has no way to be asked, so it needs Accessibility, and reaches the first nine tabs of a window), any other terminal by bringing it forward; found from the process table in `Terminals.swift`), and otherwise opens again where it last ran (`Restorer.reopen`, `Prefs.places`) with its agent's resume command, else in the terminal you used last. Its icon carries a badge of that terminal. Permission asks in a terminal show on the card but are answered there. On the card the title has its whole line; the status, in words, ends the grey line under it (the project and what you were doing). The card's body is the agent's outcome (`Recap.outcome`), not your prompt. No model writes the card: its words are the session's title and the agent's own (a long reply is read for its gist: a Summary or TL;DR first, code, tables and openers like "Let me…" skipped; a reply with nothing to quote gives way to what the agent did, `Work` and `Recap.did`, or to its short answer), and Next shows only a step the agent stated, a question it asked or a plan waiting (`Recap.statusAndNext`). On-device summaries (Apple's model) were tried and removed: they dropped facts and made others up. A file watcher (FSEvents) refreshes within about half a second.

Other agents and multiplexers. OpenCode keeps every session, its desktop app's too, in `~/.local/share/opencode/opencode.db` (SQLite, WAL, opened read-only per scan); subagent sessions (`parent_id`), archived ones and ones nobody wrote in are skipped, and a placeholder title ("New session - …") gives way to your first prompt. pi writes `~/.pi/agent/sessions/--<folder>--/<time>_<id>.jsonl`: the first line has the id and folder, entries form a tree but are always appended, and the title is the newest `session_info` name, else your first prompt. Resume with `opencode -s <id>` and `pi --session <id>`. herdr and cmux host any agent: every process in a herdr pane carries `HERDR_PANE_ID`, `HERDR_SOCKET_PATH` and `HERDR_SESSION`, and in cmux `CMUX_SURFACE_ID` and `CMUX_WORKSPACE_ID`, which `LiveSessions` reads from the process's own environment (`KERN_PROCARGS2`; herdr wins, since its server can inherit a cmux tab's values). A herdr server runs apart from any terminal, so the terminal you see it in is the one running a `herdr` client for that session (`LiveSessions.Viewer`); with none attached, Pick up opens one. Which process is which session: one whose command names the session id, or that herdr names, else the newest session of that agent in that folder active since the process started (`Running.match`). herdr's own reading of each pane (working, blocked, done) counts below hooks and above the transcript (`HerdrStatus`). Tests for these sources are in `OtherAgentsScanTests` (a real SQLite file and pi files in a fake home).

Conductor (conductor.build) runs Claude Code and Codex in a git worktree per workspace and lists them in `~/Library/Application Support/com.conductor.app/conductor.db` (`sessions.claude_session_id` holds the Claude session id or the Codex thread id, `workspaces.workspace_path` the worktree). The transcripts are ordinary ones (Claude's entrypoint is `sdk-ts`, Codex's originator `codex_sdk_ts`) and Conductor puts a `<system_instruction>` block before your first prompt, which `TranscriptParser.text` strips. `SessionScanner.claude` lists Conductor's own sessions and `codex` tags its threads (`Project.conductor`, the workspace id), archived workspaces and hidden sessions skipped. A row carries Conductor's icon with the agent as a badge (`opens` in the snapshot, app.js `AppOf`), and Pick up (`ConductorApp.open`) brings Conductor forward and presses the workspace's sidebar link through Accessibility: its address ends in `/workspace/<id>`, and Conductor has no `conductor://` link for an existing workspace. A project folded shut in the sidebar hides its links, so its row is clicked with the mouse (it offers no press action). The page's own address says which workspace is in front (`ConductorApp.showingNow`, for `youAreIn`). Reply goes in through the paste fallback: Conductor focuses its prompt on opening a workspace. A Conductor update that changes its page can leave Pick up at "Conductor, brought forward"; `ConductorScanTests` cover the database and transcripts.

Status, two sources. With live status on, hooks say exactly what happened (`LiveStatus.apply`) and win over the transcript, except a stop: Claude sends no hook for Stop or Esc, so a transcript that ends in one after the last hook wins (`LiveStatus.holds`). Claude's PermissionRequest hook runs alongside the app's own prompt, whichever answers first wins, so Perch can allow, deny or answer a question (`answers` in `updatedInput`). In Bypass permissions mode Claude sends no PermissionRequest for a question, so Perch also installs a PreToolUse hook on `AskUserQuestion` (`Ask.viaPreToolUse`, tested against a real `claude` with a temporary settings file: allow plus `updatedInput.answers` is taken as the answer). That hook blocks the app's own prompt until it returns, so it is held only for a Claude app session you are not in, for the notch's nine seconds plus the question time, and let go the moment you are in that session (`HookServer.keepHolding`); `HookInstaller.upgrade()` adds it to an earlier install at launch. Codex's runs before its prompt, so Perch answers Codex at once with no decision and only shows the status. Perch's OpenCode plugin never blocks OpenCode: a permission or question is held open beside OpenCode's own prompt, an answer from the notch goes back through OpenCode's client, and one given in OpenCode makes the plugin drop its request. pi has no permission prompts; its extension reports turns, tools, stops and extension prompts (pi 1.0+, answered in the terminal). Without hooks, status is guessed from the transcript's shape (`Recap.statusAndNext`). Test the socket without touching any config: `echo '{"session_id":"…","tool_name":"Bash","tool_input":{"command":"ls"}}' | ~/.config/perch/hook claude PermissionRequest` (it waits for your answer on the card). Post test questions this way, to an idle session: a message sent in a Claude session while its question is open dismisses the question.

While you work, an answer or a request in a session you are not in shows as a live activity (`NotchController.youAreIn`: the sessions you are in or may be in never get one; `UISnapshot.activeIds`, app.js `inside`; `PERCH_TRACE=1` logs `Perch in:`): the notch grows with the project beside the camera and what happened, and below, the session's title and a row of buttons on Command+Option keys registered only while it shows (a small cross at the left of the row puts it away, as does Command+Option+.) (app.js `activity`; `./scripts/run.sh --activity` plays it). A finish folds away; a request folds to wings until answered; a stop on an error (nothing to answer) says so once and folds away, and does not come back for the same error (`actErr`).

When the welcome card speaks up: only on return from a break, only if a session changed since you last saw it (finished, asked, stopped) and since your last break or within the last day (`WhileAway.newsSince`; older is history, and a guessed "needs you" from then reads as idle, `Project.settled`), never during a call, camera or presentation, nor while a launcher such as Raycast has the keyboard (`Quiet`; it shows once that is over), and never during a "Not now". "Seen" is per session, in UserDefaults: a second on the welcome card, a Pick up, or being the session you are in. The Claude app's own `lastFocusedAt` counts too: a session you had in front there since it changed is not news, and the one it focused last is the session you are in.

## Running and building

```bash
cd ui && npm install && cd ..       # once
./scripts/make-dev-cert.sh          # once: stable signing identity so macOS keeps permissions
./scripts/run.sh --show             # build and launch, show the card
./scripts/run.sh --idle 15          # welcome card after 15 s idle (testing). Relaunch without it afterwards.
swift test
./scripts/package.sh                # build/Perch.zip for sharing
./scripts/release.sh [--publish]    # a release that installed copies update to (Sparkle), see Updates
./scripts/make-dmg.sh               # build/Perch.dmg: the window people drag Perch to Applications in (release.sh makes and uploads it; the zip stays what Sparkle updates from)
node scripts/render-dmg-background.mjs  # Resources/dmg/background.png and @2x from ui/install/background.html (the design page's Installing tab shows it)
./scripts/make-icon.sh              # Resources/AppIcon.icns and docs/assets/icon.png from docs/assets/icon.svg (WebKit draws the coat)
./scripts/pr-demo.sh [scenario...] [--publish]   # a PR's demo from the design page (see Opening a PR)
./scripts/agents-demo.sh [folder]   # herdr with pi, OpenCode, Claude Code and Codex side by side, and pi alone, in cmux
```

Useful flags: `--show`, `--simulate`, `--onboarding` (replays it from the hello), `--hello` (the hello beside the notch after setup), `--demo`, `--idle <s>`, `--snapshot <dir>`, `--dump` (prints what the scan finds), `PERCH_TRACE=1` for state logging.

## Updates

Perch updates itself with Sparkle (`Sources/Perch/Updater.swift`), with no Apple notarization. `SUFeedURL` in `Resources/Info.plist` points at `appcast.xml` in the public repo `asafofer/perch-releases` (the source repo is private); the zips are that repo's release assets. Each update is signed with an EdDSA key (public half `SUPublicEDKey` in the plist, private half in the owner's login keychain, made by Sparkle's `generate_keys`: lose it and installed copies can never update, so keep a backup). It checks daily, downloads and installs in the background, and a downloaded update restarts Perch only when `NotchController.isQuiet` (nothing open, no draft). A test build (`PerchTestBuild`) and any `--fake`, `--demo` or `--snapshot` run never update. It has Perch's own face, not Sparkle's windows: `Updater` is Sparkle's user driver, and the page draws it (app.js, "an update of Perch itself"; the design page's Updates tab plays every state; `./scripts/run.sh --update-demo` plays it over the real notch). A check on a schedule that finds an update downloads it (the character and a ring with an arrow beside the camera), then restarts at a quiet moment ("Updating", then a small "Updated" row); Check for updates in the menu offers it first (Update, Later, What's new). While the list or a card is open it waits as a blue chip at their top right (Update, the ring, Restart). The buttons have no keys: the notch never takes the keyboard when it opens by itself. When an update does not go through, the row says why and what to do instead of a bare "Couldn't check": `UpdateProblem.classify` (PerchCore, tested) reads Sparkle's error and the ones inside it (a download that failed offline carries the network's error) into a notch line, a few words for Settings, and a fix: Try again, Show in Finder (Perch running from Downloads or a folder it cannot write to: macOS runs a downloaded app from a read-only copy that nothing can replace, `SURunningTranslocated`; Show in Finder reveals where it was unzipped), or nothing. A Mac that cannot run the newest release (Intel, or macOS too old) is told so rather than "up to date" (`UpdateProblem.noUpdate`). Only a check you asked for or an update already on its way says it failed; a failed scheduled check stays quiet. Perch still here 20 s after the restart began says it could not quit, and Try again asks Sparkle to quit it once more. The design page's Update errors category plays every case, in the notch and in Settings. `release-notes/<version>.md` (a headline line, then `- ` lines; any number, six show and the rest scroll) is embedded in the appcast and read by `UpdateNotes`. Sparkle's version compare uses the build number, the commit count, so a release must be cut from a commit newer than the last. `release.sh` builds, signs and writes the appcast; `--publish` makes the GitHub release and pushes `appcast.xml`. Every release must be signed with the same "Perch Dev" certificate, otherwise macOS asks for Accessibility again after the update. To test an update without publishing, build two copies with different `CFBundleVersion` and a `SUFeedURL` on localhost, serve a folder with `generate_appcast` output, and launch the older copy outside /Applications.

## Design rules (the owner is firm about these)

- Linear-grade restraint. Neutral sans (Inter), tight tracking, sentence case, small type (card text 13 to 14 px), small call-to-action buttons.
- **No dividing lines.** No pulsing or glowing dots (the list's status rings have a faint, still glow; nothing else). No drawn icons where a real app icon exists (use the real Claude, Codex and OpenCode icons from `AppIcons`). pi has no app, so the page draws pi.dev's own mark; OpenCode's opencode.ai mark stands in when its app is not installed.
- The character is a soft plush shape with flat, matte eyes. Its depth is one SVG filter on the body (`coatFilter` in `app.js`): light from the top left, a rounded form, shade that deepens its colour, a rim of light, and from 30 px up a fuzzy edge and faint grain. Small, it keeps a crisp outline. Nothing else goes on the character. Shapes live in `SHAPES` in `app.js`.
- Glow is internal, soft, and tinted by status: orange needs you, green done, otherwise the character's colour. Dithering was tried and rejected.
- Never suggest committing, pushing or merging as the "next step". Hide the Next row when there is nothing real to say.
- Pick up closes the card at once. No success screen.
- Perch must never take the keyboard when it opens by itself, and never nudges about the session you are already in. A card you hover open takes it only when it shows something to answer (`cardTakesKeys`): otherwise a number or Esc lands in the agent's own prompt behind it, and Esc there dismisses the question. A card takes the keyboard once (on opening, or as the pointer comes onto it) and leaves it with whoever takes it next: Raycast closes the instant it loses focus. When another app takes the keyboard, or a launcher has it (`Quiet.launcherOpen`, an app other than the one in front, read through Accessibility), the card makes way (`makeWay`), except during onboarding or a reply.
- Motion should feel alive but rare. Respect `prefers-reduced-motion`.

## Things that will bite you

- `ui/app.js` is kept ASCII-only (non-ASCII as `\uXXXX`) because the file is loaded without a charset in places. After editing, check: `python3 -c "print(all(ord(c)<128 for c in open('ui/app.js').read()))"`.
- WebKit sends a card hovered open no pointer moves until it is clicked. Perch passes the pointer to the page (`cursor`), which marks what is under it `.hv` (`hoverAt`). Tailwind's `hover:` also matches `.hv`; a hand-written `:hover` rule in `input.css` needs a `.hv` twin.
- JS name clashes are silent: a second `var COLORS` once broke status colours. Check names before adding globals.
- Browsers cache `dist/ui.css` and `app.js` hard. In the design page, reload with `fetch(url, {cache: 'reload'})` after rebuilding CSS (`cd ui && npm run build`).
- Tailwind classes are generated from strings in `app.js`. Rebuild CSS after adding classes.
- macOS TCC permissions are tied to the code signature. Without the "Perch Dev" certificate the app is signed ad hoc and macOS asks again after every build.
- Accessibility is needed for Command+Option and for pasting replies. `AXIsProcessTrusted()` can lag after granting; onboarding offers a restart.
- The panel is one fixed transparent window (480 x 410 plus a 10 pt overscan above the screen). Cards must fit inside it.
- Self-signed and ad-hoc builds cannot register for launch at login reliably.
- Opening a notch app over full-screen apps depends on window level and collection behavior; see `NotchPanel`.
- The settings and onboarding cards must fit the panel (410 pt). Settings rows are 30 pt apart whatever shows (348 pt with nine rows, 408 with all eleven: an external display and no Accessibility), so adding a row needs the panel to grow. Measure `.p-set .inner` and `.p-onb .inner` in the design page after adding a row.
- Hooks only change behaviour once installed (Settings, Live status). Codex skips a new hook until you trust it once. Never write to `~/.claude/settings.json` or `~/.codex/hooks.json` except through `HookInstaller`, which only touches its own entries; for OpenCode and pi it writes and removes only its own file (`~/.config/opencode/plugins/perch.js`, `~/.pi/agent/extensions/perch.ts`, first line `// Perch:`). Try the installer with `PERCH_HOME=<folder> .build/debug/Perch --install-hooks`, and a plugin against a stand-in socket before it reaches real config.
- cmux's command line tool only answers processes inside cmux (its default socket mode), so Perch drives cmux through AppleScript: a terminal's `id` is the `CMUX_SURFACE_ID` its processes carry. `input text` pastes (bracketed), so Return is sent separately with `perform action "text:\\r"`.
- Codex 0.162's terminal app writes `source: "vscode"` like the Codex app; `originator: "codex-tui"` is what says terminal.
- An agent or multiplexer started from inside another app's terminal (this one, an editor's) inherits that app's variables: Claude Code started that way records itself as the Claude app (`entrypoint: claude-desktop`) and drops out of the terminal list. `agents-demo.sh` starts herdr with `env -i` for this reason.
- herdr's `pane run`, `send-text` and `send-keys` print nothing when they work: judge herdr actions by exit status (`Herdr.act`). A herdr server brings its last layout back when it starts.
- macOS hides the environment of system binaries (`/bin/sleep`) from `KERN_PROCARGS2`; agents are not system binaries. node renames itself (pi's argv[0] is `pi`) and leaves empty strings where its arguments were.
- Seeing the real panel: computer-use screenshots hide it. Use `screencapture -x -R 496,0,520,340 out.png` with keys sent by `osascript`, in the same command (a card that Perch opened by itself closes after 9 s).

Displays. Settings → Show Perch on (`Prefs.showOn`, `ScreenTarget`) decides where the shortcut opens Perch and where it shows up by itself (live activity, welcome card, a snooze coming due, an update): the screen with the mouse (the default), the screen with the active window (the front layer-0 window of the app in front, from the window list, `FrontWindow`; none means the mouse), or one display by its UUID (`NSScreen.displayID`; one not connected stays in the menu greyed, with the name it had, `Prefs.showOnName`, and until it is back Perch follows the mouse). `ScreenChooser.target()` is that screen; `rest()` is where the panel waits while nothing is open: with the mouse it follows the cursor as always, otherwise it waits on the target. A hover always opens Perch on the hovered screen: in the fixed modes the panel moves to a screen whose hover zone the cursor enters and goes back once it leaves (`followHoverWhileFixed`). A display with no notch shows nothing at rest: Perch opens there with the hotkey and shows the live activity from the top edge; the Show Perch on menu ends with a Hover opens on external displays switch (`Prefs.hoverExternal`, off by default, shown only while such a display is connected) that lets the top edge open it too. Hover only counts on the screen the cursor is on, because the hover zone reaches above its screen's edge (`overNotch`, `NotchGeometry.hovering`). `--dump` prints the screens, their ids and where Show Perch on points now. The resting notch on a Mac with one is drawn a point inside the size the system reports, with smooth corners (app.js `notchPath`), so it hides behind the hardware; `PERCH_NOTCH_GUIDE=1` paints it magenta at the full reported size to see any overhang.
